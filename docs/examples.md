# Examples

Runnable scripts in `examples/`, using synthetic data generated by
`examples/generate_sample_data.py` (simulates a 15-second cyclical motor
task with three known ground-truth synergies, so extraction results can be
checked against a known answer). Generate it once before running any
example:

```bash
python examples/generate_sample_data.py
```

## 01 — Basic envelope extraction

`examples/01_basic_envelope.py` loads the synthetic raw EMG and extracts
the adaptive envelope with {func}`musyn.extract_envelope`.

```{image} _static/examples/01_envelope.png
:alt: Adaptive envelope extraction on synthetic 8-channel sEMG
:width: 100%
```

## 02 — Synergy extraction

`examples/02_synergy_extraction.py` extracts 3 synergies from the (known)
envelope with {func}`musyn.extract_synergies` using SPARSE initialization,
and reports {func}`musyn.quality_ratio` and {func}`musyn.vaf` against the
ground truth.

```{image} _static/examples/02_synergies.png
:alt: Extracted synergy weights and activation time courses
:width: 100%
```

## 03 — Synergy number selection

`examples/03_synergy_number_selection.py` runs {func}`musyn.select_synergy_number`
over a range of `k` and plots the resulting AIC curve, confirming the
minimum lands at the ground-truth `k=3`.

```{image} _static/examples/03_aic_curve.png
:alt: AIC curve over candidate synergy counts, minimized at k=3
:width: 100%
```

## 04 — Full pipeline

`examples/04_full_pipeline.py` chains everything together on the same
synthetic dataset: raw sEMG → adaptive envelope → automatic `k` selection →
synergy extraction → quality metrics. This is the script {doc}`quickstart`
is based on — read it alongside that page for the complete annotated
walkthrough.

```bash
python examples/04_full_pipeline.py
```

## Notes on the example data

The synthetic dataset (`examples/data/sample_emg.npz`) models three
functionally distinct synergies — an agonist (four bursts with mild fatigue
progression), an antagonist (four alternating bursts), and a stabilizer
(active during transitions, overlapping both) — precisely so that
{func}`musyn.quality_ratio` has a meaningful ground truth to compare
against. Real recordings are, of course, the actual target use case; the
synthetic set exists purely so the examples (and the test suite — see
{doc}`contributing`) don't depend on real subject data.
